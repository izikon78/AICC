## Evidence issues to retain and resolve

### 1. The article/audit describe a different Claude Round 8 artifact set

The supplied [GPT-6 audit](../../agents/gpt6/round8/AI_Think_Tank_Round8_Independent_Audit.md), Draft 4 PDF, and detailed handoff discuss seven contract reimplementations with **14,000** fuzz agreements, two implementations with **3,127/5,000** disagreements, and an initial **18/20** result repaired to 20/20. The audit explains that one alternative violated an output-order rule already stated in its contract; the disagreements therefore do not prove that particular rule was omitted.

The supplied [Claude Round 8 report](../../agents/claude/round8/Round8_Results_Claude_Opus_5.5.md) and matching code/logs archive instead record first-attempt 20/20, a candidate YAML contract, and **1,206-vector** Python/JavaScript comparisons. They do not contain the audit's named `multiagent_contract.py` or both of its described implementations.

Preserve both accounts as separate historical evidence. Recover the exact audited revision, logs, and hashes before pooling these measurements or claiming the earlier extended audit was reproduced from this collection. The current import rerun verifies only the supplied official-suite submissions.

### 2. Gemini's initial case counts were corrected; token counts still need reconciliation

The original [Gemini Round 8 report](../../agents/gemini/round8/ai_think_tank_round_8_experiment_results_gemini.md) reported 24/24 and file sizes that differed from the frozen packet. The [Round 8.1 correction](../../agents/gemini/round8/ai_think_tank_round_8_1_correction_reconciliation_gemini.md) explicitly changes this to **20 official workflow cases plus three mock security checks** and attributes earlier sizes to preliminary draft variants. The restored verifier contains those 20 workflow cases.

Do not keep citing 24/24 as the official result. The correction's stated `API_CONTRACTS.md` tokenizer count also differs from Claude's count for the frozen file. This import verified bytes/hashes, not tokenizer measurements; retain the discrepancy until the same tokenizer/vocabulary and exact file bytes are rerun together.

### 3. Precise Gemini efficiency assertions lack supporting trials

The supplied [Gemini efficiency report](../../agents/gemini/efficiency/aicc_efficiency_independent_research_report.md) asserts a **14.2%** syntax-error increase, a **ten-use** economic break-even, **0.15–0.50 ms** binding overhead, and combined symbolic/AICC workflow success. The supplied [efficiency synthesis](AICC_Efficiency_Research_Review_Copy.pdf) identifies missing trial details, raw timing/cost records, and complete executable language support for these assertions.

Archive those assertions as contributor claims requiring evidence. They are not established measurements of AICC's economics. The trained native-token hypothesis remains untested; strong “rejected” or “validated” labels in historical reports should not be promoted to project conclusions without the relevant experiment.

### 4. Correctness and mock security do not establish the main benefits

Conventional reuse succeeds without implementation-source reading in the same small fixtures. The available reports do not demonstrate an incremental economic benefit over that strong baseline. Artifact bytes or tokenizer counts are not billed model usage; execution timings of finished code are not agent development time.

The three passing mock checks coexist with bypasses documented in Claude's report. Caller-asserted scopes, declared effects, a disk hash, and an in-process callable do not create a production private boundary. The restored `sealed/` directory is a historical benchmark convention, not confidential project code or an actual hidden-test service; publishing it prevents treating these public fixtures as unseen evaluation tasks for future agents.
