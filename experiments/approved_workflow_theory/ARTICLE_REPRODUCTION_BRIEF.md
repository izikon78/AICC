## Question and premises

Given fluent use of an already existing optimized machine-oriented representation
and fully approved reusable capabilities, how much context and output position
demand could an agent avoid while composing, changing, repairing and handing off
workflows compared with conventional Python using the same capabilities?

The experiment treats the language's existence, fluent knowledge and core
approval as premises. It additionally assumes correct composition through
predefined oracle plans. New requirements, business parameters, arguments,
working records, memory, tool observations and repeated context are charged.
These assumptions isolate a conditional encoding mechanism.

AIN is the project's working label for AI Native Language. AICC is AI
Computational Commons, the separate reusable-capability architecture. Shared
approved capabilities are equal across this experiment's conditions. The
experiment studies the representation and accounting consequence of that premise.

## Reproduced observations

The suite has eighteen four-stage chains covering event processing, cache
version/expiry resolution and deterministic publication/retry simulation. Six
parameter/data variants share each domain's composition template. Every pipeline
uses five generic approved functions. The approved core contains ten public
functions, four explicit `for` loops, one `while` loop and seven comprehensions.

Each data schedule contains seventy-two executed stages and 216 logical agent
requests. Build writes a composition, change patches a parameter, repair patches
one injected defect and handoff uses the saved artifact and memory. All stages
passed independent output checks. Both Python renderings round-trip to the same
semantic plans and approved implementations.

| Schedule | Short-alias Python input | Python output | Ideal input | Ideal output | Total reduction |
|---|---:|---:|---:|---:|---:|
| Resident data | 34,686 | 5,928 | 27,144 | 3,714 | 24.02127345% |
| Inspect records | 70,470 | 5,928 | 62,928 | 3,714 | 12.76996780% |

Resident-data totals are 40,614 and 30,858. Inspect-data totals are 76,398 and
66,642. The ideal AIN, ideal readable-IR and ideal Python interfaces have the same
counts by construction under equal semantic encoding opportunities.

Practical Python counts use the frozen Qwen2.5-1.5B text tokenizer. Ideal counts
use a fixed 65,536-entry code-unit accounting model. The model charges a learned
operation reference, typed operands and explicit literal payloads. Common task
inputs use identical text in every condition. The total-position comparison
assumes equal cost per text token or ideal code unit.

## Suggested article statement

> Under a frozen accounting model that grants a fluent optimized representation,
> approved shared capabilities and correct composition, the executable workflow
> cases required 24.0% fewer counted total positions than short-alias Python when
> business data stayed behind a host handle, and 12.8% fewer when records were
> included in context. Equivalent ideal IR and Python interfaces achieved the
> same counts. These are conditional representation/accounting results.

The integer ledgers support those percentages. Publication claims should preserve
the premises, comparison units, shared-capability control and equal ideal-interface
result. GPU latency, energy, API prices, trained-agent task success and learning
amortization remain separate empirical questions.

## Evidence an independent agent should return

The agent should provide its exact Git revision, environment and dependency
versions, tokenizer identity and revision, source/fixture hashes, check outcome,
fresh raw observations and comparison report. It should show exact integer totals
for both schedules and verify the input, output, artifact, memory and reprocessed
history ledgers. Explain any discrepancy at the earliest differing field.

For independent reconstruction, include the independently written counter and
renderer, their code hashes and the order in which reference materials were
consulted. Preserve the initial ledger even if the comparison reveals an error.
Describe the cause, then place a corrected attempt in a fresh directory with its
own provenance. The frozen specification determines expected counting behavior.

Host timings are diagnostic observations and can vary across machines. The
primary reproduction target is the deterministic fixture behavior and count
ledger. Preserve failed attempts and environment changes in the independent
report. Include the source of any deviation before interpreting its result.

Keep exact reproduction and extensions in separate versions. A changed tokenizer,
vocabulary capacity, literal encoding, framing rule, workload or context policy
changes the accounting question. A model-based extension should also record
actual inference, correctness, failed attempts, repairs and learning/setup costs.

## Interpretation limits

The workload suite supplies three fixed composition templates with parameter and
data variants. The two schedules replay the same tasks under different data
exposure policies. Functions and loops execute inside the approved core, while
the agent-authored artifacts compose those capabilities and patch their arguments.
The suite demonstrates executable accounting examples under its premises.

Perfect composition is an additional assumption. The fixed fifteen-bit payload
and vocabulary model determine ideal code-unit counts. The equal ideal controls
identify a shared compact-interface mechanism. Further evidence would be needed
to assign an extra advantage to a particular spelling or to estimate actual
trained-agent resource savings on new workflow structures.
